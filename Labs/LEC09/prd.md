# 소닉 애니메이션 뷰어 PRD

## 1. 목적 및 개발 범위

`pre-prd.md`의 초기 요구사항과 이후 확정한 화면 크기를 반영한 개발 기준 문서다. 제공된 스프라이트 시트의 모든 동작을 자동으로 순차 재생하는 뷰어를 제작한다.

| 항목 | 개발 기준 |
| --- | --- |
| 개발 환경 | Python + `pico2d` |
| 작업 위치 | `Labs/LEC09` |
| 소스 파일 | `sonic_animation_viwer.py` 단일 파일, 초기 요구사항의 파일명 유지 |
| 이미지 | `sonic-sprite.png`, 소스 파일 위치를 기준으로 로드 |
| 화면 크기 | **가로 1200 × 세로 800 픽셀** |
| 재생 방식 | 동작별 **5회 반복 → 1초 대기 → 다음 동작**, 전체 무한 반복 |
| 종료 | 창 닫기 또는 `ESC` |
| 개발 방식 | 단계별 구현·검증, 총 **20~22개 커밋** 목표 |

별도 이미지나 외부 UI 라이브러리는 사용하지 않는다. 동작 선택, 속도 조절 UI, 이미지 편집 및 내보내기는 이번 개발 범위에 포함하지 않는다.

## 2. 재생 요구사항

- 실행 즉시 첫 동작부터 자동 재생하며, 시트의 모든 동작을 정해진 순서로 표시한다.
- 첫 프레임부터 마지막 프레임까지 각각 지정된 시간 동안 표시하면 1회 재생으로 계산한다.
- 1~4회 완료 시 같은 동작의 첫 프레임으로 돌아간다. 5회 완료 시 마지막 프레임을 유지하며 1초 대기한다.
- 대기 후 다음 동작의 첫 프레임부터 재생한다. 마지막 동작 이후에도 동일하게 대기하고 첫 동작으로 돌아간다.
- 다음 동작에 진입할 때 프레임 번호, 반복 횟수, 해당 상태의 시간 누적값을 초기화한다.
- 단일 프레임 동작은 프레임 표시 시간 하나를 1회로 계산한다.
- 대기 중에도 화면 갱신과 종료 입력 처리를 계속한다.

## 3. 화면 및 프레임 데이터

- 캔버스를 **1200×800**으로 생성한다. 정지 동작은 중앙에, 이동 동작은 이동 거리와 방향을 반영한 위치에 충분히 크게 표시한다.
- 원본 비율과 전체 동작의 공통 확대 배율을 유지한다. 가장 큰 프레임도 여백을 두고 화면 안에 들어오도록 배율을 정한다.
- 프레임별 중심과 발 기준선을 맞춰 불필요한 흔들림을 줄이되, 점프 등 동작 자체의 의도된 이동은 유지한다.
- 매 프레임 배경을 지우고 다시 그려 잔상을 방지한다.
- 시트를 분석해 동작별 이름, 재생 순서, 프레임 영역 `(x, y, 너비, 높이)`, 필요한 정렬 보정값을 정의한다.
- 프레임이 일정한 격자로 배치됐다고 가정하지 않는다. 인접 프레임이나 다른 동작이 섞이지 않도록 영역을 확인한다.
- 위쪽 기준으로 측정한 이미지 좌표는 `pico2d`의 아래쪽 기준 좌표로 변환한다.

### 이동 표현 추가 요구사항

- 걷기·달리기·구르기·회전·대시는 동작별 한 주기 이동 거리를 정의하고 재생 시간과 확대 배율을 반영해 이동한다.
- 공중 회전은 전진과 포물선 상승·하강, 피격은 뒤로 밀림, 제동은 한 주기 내 감속을 표현한다.
- 같은 동작의 5회 반복 동안 이동 거리를 누적한다. 1초 대기에는 마지막 위치를 유지하고, 다음 동작 시작 시 해당 동작의 시작 위치로 초기화한다.
- 화면 가장자리에서는 자연스럽게 퇴장하고 반대편에서 재진입한다. 이 과정의 의도된 화면 경계 잘림은 허용한다.
- 원본 시트에는 물리적 이동 거리 정보가 없으므로 동작별 이동량은 조절 가능한 시연 값으로 정한다.

## 4. 구현 구조

단일 소스 안에서 설정과 프레임 데이터, 입력 처리, 상태 갱신, 그리기, 실행 및 종료 처리를 함수로 분리한다.

| 구성 | 역할 |
| --- | --- |
| 설정 | 화면 너비 `1200`, 높이 `800`, 애니메이션 FPS, 확대 배율, 반복 횟수 `5`, 대기 시간 `1.0초`를 상수로 관리 |
| 상태 | 현재 동작, 프레임 번호, 완료한 반복 횟수, 누적 시간, `PLAYING`/`WAITING` 관리 |
| 실행 루프 | 입력 처리 → 경과 시간 계산 → 상태 갱신 → 그리기 |
| 시간 처리 | 프레임 표시 시간은 `1 / FPS`로 계산하고 누적 경과 시간으로 전환 |
| 오류 및 종료 | 이미지 로드 실패 시 경로를 포함한 오류 안내, 종료 시 캔버스 자원 정리 |

애니메이션 속도는 화면 갱신 횟수에 의존하지 않도록 한다. 1초 대기는 실행 루프를 멈추는 긴 블로킹 호출 대신 상태와 경과 시간으로 처리한다.

## 5. 단계별 개발 계획

작은 기능을 구현하고 확인한 뒤 커밋한다. 완성 코드를 한 번에 작성한 뒤 커밋만 나누거나, 빈 커밋으로 개수를 채우지 않는다.

| 단계 | 작업 및 확인 내용 | 커밋 수 |
| --- | --- | --- |
| 1 | 시트 분석, 전체 동작 목록, 프레임 좌표와 재생 순서 정의 | 4 |
| 2 | 1200×800 창 생성, 이미지 로드, 정적 프레임 표시, 확대 및 정렬 | 4 |
| 3 | 시간 기반 재생, 동작별 프레임 전환과 표시 시간 확인 | 4 |
| 4 | 5회 반복, 1초 대기, 다음 동작 전환, 전체 무한 순환 | 4 |
| 5 | 종료 및 오류 처리, 전체 동작 검증, 수정과 코드 정리 | 4~6 |

동작 수, 프레임 좌표, 기본 애니메이션 FPS와 확대 배율은 시트 분석 및 표시 확인 후 확정한다. 화면 크기는 1200×800으로 확정되어 있다.

## 6. 검증 및 완료 기준

| 확인 항목 | 통과 기준 |
| --- | --- |
| 실행 및 파일 경로 | 다른 작업 경로에서 실행해도 소스 위치의 이미지를 로드한다. |
| 화면 크기 | 캔버스가 1200×800으로 생성된다. |
| 동작 및 프레임 | 시트의 모든 동작이 누락이나 중복 등록 없이 올바른 영역과 순서로 표시된다. |
| 반복과 대기 | 정확히 5회 재생하고, 마지막 프레임 표시 시간이 끝난 뒤 1초 대기한다. |
| 전체 순환 | 마지막 동작에서 첫 동작으로 돌아가 두 번째 순환도 정상 진행한다. |
| 확대 및 정렬 | 캐릭터가 충분히 크고, 잘림·잔상·불필요한 위치 흔들림이 없다. |
| 종료 및 오류 | 재생·대기 중 종료가 가능하고 이미지 누락 시 원인을 알 수 있다. |
| 산출물 및 이력 | 단일 소스 파일과 단계별 개발 커밋 20~22개를 확인한다. |

위 기준을 모두 확인하면 개발 완료로 판단한다.
